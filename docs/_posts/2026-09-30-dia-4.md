## Instalación de mjlab

- La versión actual de mjlab (1.6.0) exige MuJoCo 3.11; yo tenía la 3.3.7.
- Paso el repositorio a [uv](https://docs.astral.sh/uv/): `pyproject.toml` y `uv.lock` sustituyen a `requirements.txt`, y el entorno está en `.venv/`.
- `uv add mjlab==1.6.0` instala también MuJoCo 3.11, MuJoCo Warp, PyTorch y RSL-RL.
- Comprobado que mi modelo del UR5e sigue cargando con MuJoCo 3.11.
- `uv run list-envs` muestra las tareas que trae mjlab, entre ellas `Mjlab-Lift-Cube-Yam` (sin cámara), `-Depth` y `-Rgb`.

## Prueba: brazo YAM levantando un cubo (sin cámara)

Comando:

```bash
uv run train Mjlab-Lift-Cube-Yam --env.scene.num-envs 1024 --agent.logger tensorboard
```

- `--env.scene.num-envs 1024`: 1024 brazos simulados a la vez (por defecto es 1).
- `--agent.logger tensorboard`: guarda las gráficas en local (por defecto usa wandb, que pide cuenta).
- `--agent.max-iterations`: por defecto 5000.

Prueba corta (100 iteraciones): ~38 s.

Entrenamiento completo (5000 iteraciones):

| Dato | Valor |
|---|---|
| Duración | 57 min |
| Velocidad | ~35.000–55.000 pasos/s |
| Memoria GPU máxima | 1203 MB de 6144 |
| Uso medio de GPU | 88 % |
| Temperatura máxima | 66 °C |
| Potencia media | 99 W |

| Iteraciones | Éxito medio |
|---|---|
| 0–499 | 28 % |
| 500–999 | 72 % |
| 1000–4999 | ~71 % |

- Aprende casi todo en las primeras ~750 iteraciones y luego se estanca en ~70 %.
- Los choques de la pinza con el suelo bajan del 25 % al 5 % de los intentos.
- Sin NaN durante todo el entrenamiento.
- Para ver las gráficas he empleado TensorBoard.

## Conclusiones

- La tarea sin cámara es cómoda en mi portátil: usa menos del 20 % de la memoria.
- Con ~1000–1500 iteraciones (~12–18 min) basta para esta tarea; entrenar más no mejora.
- Para pasar del ~70 % habría que cambiar el diseño de la tarea, no entrenar más tiempo.
- Falta probar la versión con cámara, que es la que más memoria y tiempo gasta.
